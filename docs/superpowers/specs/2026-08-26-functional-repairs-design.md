## Contact Form Architecture

### API boundary

Create `api/contact.ts` at the root of `vincent-os-2d`. Vercel deploys this file
as the same-origin `/api/contact` function. The React form must use this relative
path so previews, production, and custom domains use the same code.

The endpoint accepts only `POST` with JSON containing:

- `name`: required, trimmed, 1-100 characters.
- `email`: required, trimmed, valid email syntax, at most 254 characters.
- `company`: optional, trimmed, at most 120 characters.
- `message`: required, trimmed, 1-5,000 characters.
- `website`: hidden honeypot; a non-empty value is treated as a bot submission.
- `submissionId`: required UUID generated by the browser and retained when the
  visitor retries a failed submission.

Malformed JSON, missing fields, invalid values, and unsupported methods return a
non-2xx response with a stable JSON shape:

```json
{
  "success": false,
  "error": "Human-readable message"
}
```

A successful request returns HTTP 200:

```json
{
  "success": true
}
```

For honeypot submissions, return the same success response without sending mail
so bots cannot use the response to tune their behavior.

### Email delivery

The Vercel Function uses the Resend SDK with server-only environment variable
`RESEND_API_KEY`. It sends:

- From: `Vincent Fang Portfolio <portfolio@fzvincent.com>`
- To: `15070654315@163.com`
- Reply-To: the visitor's submitted email address
- Subject: includes the visitor name and optional company
- Body: plain text containing the submitted fields

The API key must never be added to source control or exposed with a
`REACT_APP_` prefix. Resend errors are logged server-side without logging the API
key, and the browser receives a generic send-failure message.

Use `contact-${submissionId}` as the Resend idempotency key so a browser or
network retry does not generate duplicate messages within Resend's idempotency
window.

### Form behavior

The React form submits to `/api/contact`, prevents duplicate submissions while a
request is active, clears fields only after success, and keeps entered values on
failure. It exposes a visible status message and an appropriate live region for
screen readers.

The form's React-side validation mirrors the API constraints for quick feedback,
but the server remains authoritative. Chinese and English modes use localized
field labels, validation messages, progress text, success text, and failure
text.

## React Lifecycle Repair

The custom showcase `Link` component currently returns a cleanup function from
an event handler. React ignores that returned function, so delayed state updates
can run after navigation unmounts the component.

Move timer ownership to refs and clear every pending timer in an effect cleanup.
Navigation behavior and the short active-state animation remain unchanged. The
repair must not alter route destinations or visual styling.

## Testing Strategy

Implementation follows red-green-refactor. Each behavioral change begins with a
test that fails for the current implementation.

### Automated API tests

- Reject non-POST methods.
- Reject malformed JSON.
- Reject missing, invalid, and oversized fields.
- Accept an optional empty company.
- Suppress mail for a filled honeypot while returning success.
- Return success when the mail boundary succeeds.
- Return a stable generic failure when Resend fails.
- Verify destination, sender, reply-to, subject, and body mapping at the Resend
  boundary.

### Automated React tests

- Enable the contact submit button only for a valid form.
- Show sending, success, and failure states correctly.
- Preserve form values after failure and clear them after success.
- Render localized Contact UI in Chinese and English.
- Unmount navigation links with pending timers without producing a React state
  update warning.
- Fall back to English for an unknown non-empty translation key.

### Build and browser verification

- Run the full automated test suite in each changed repository.
- Run `npm run build` successfully in both repositories.
- Locally verify 2D navigation, Contact, language switching, Start menu,
  Vinordle, and Doom.
- Locally verify 3D boot, scene entry, embedded 2D loading, and monitor input.
- On Vercel preview deployments, verify `/api/contact` error handling without
  sending a real email.
- After production DNS, Resend verification, and environment configuration,
  submit one real form message and confirm it arrives at
  `15070654315@163.com`.
